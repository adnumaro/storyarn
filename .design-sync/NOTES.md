# design-sync notes — Storyarn

- **2026-09-01, second sync — full Vue component bundle, by explicit user choice** ("quiero usar claude design para los componentes de vue"). Supersedes the styles-only scope of the first sync (same day). The app's real Vue 3 components are compiled (esbuild + unplugin-vue) and exposed as React components via a mount-wrapper harness. **Nothing is reimplemented** — reka-ui compounds that can't be composed across the React/Vue boundary (provide/inject would split per wrapper) are exposed through thin props-driven adapter SFCs that compose the app's own subcomponents.
- **Build lives in `.design-sync/bundle-src/`** (committed): `pnpm install --ignore-workspace` once, then `node build.mjs` → `<repo>/ds-bundle/` (untracked). `node verify.mjs` (needs `python3 -m http.server 8123 -d ds-bundle` running) renders every card headless via the root repo's Playwright and screenshots to `.verify/`. All 35 components + 3 foundations cards verified clean on this sync.
- **Key mechanics** (see `harness/wrap.ts`): per-instance Vue app with vue-i18n (en catalog, explicit imports — the app's `i18n.ts` glob is vite-only), a `_live_vue` stub (9 components call `useLive`; events log, never send), React children → Vue slots via `display:contents` placeholder + `ReactDOM.createPortal` (works through reka teleports — Sheet/Dialog verified with fields inside), prop aliases mapping React idiom (value/onChange, checked/onCheckedChange, open/onOpenChange) to Vue models. React/ReactDOM come from page globals; `_vendor/` ships UMD 18.3.1 for the cards.
- **Tailwind CSS**: `_ds_bundle.css` = Tailwind v4 utilities scanned from `assets/app/components` + adapters + demos (theme mirrors `app.css` `@theme inline` + dark custom-variant) + SFC styles. Imported from `styles.css` (skill invariant). Token values still come from `tokens/colors.css` at runtime.
- **Never run any vite command or mix asset task for this** (standing user rule). esbuild + the local tailwind CLI binary only. **Never `pnpm exec` from bundle-src either** — pnpm walks up to the repo root/worktree and auto-installs (fails on `file:deps/live_vue` in a worktree without mix deps; silently touched root node_modules in the main tree). Call `node_modules/.bin/<tool>` directly (build.mjs does).
- **Worktrees**: this sync ran in `.claude/worktrees/design-sync-vue-components` because another agent worked the main tree. Node resolution from a worktree under `.claude/worktrees/` walks up to the MAIN repo's `node_modules` automatically — no root install needed in the worktree; only `bundle-src/node_modules` matters (copy or reinstall).
- **Registry** (`registry.json`) is the source of truth: 35 components — 14 direct-wrapped primitives/domain (Button, Badge, Input, Textarea, Label, Switch, Checkbox, Separator, Progress, Toggle, ScrollArea, SaveIndicator, UserAvatar, ConfirmDialog), 11 adapters (Select, DropdownMenu, Tabs, Dialog, Popover, Tooltip, RadioGroup, ToggleGroup, Sheet, Collapsible, Table), 10 form/domain fields (TextField, NumberField, SelectField, ToggleField, SliderField, ButtonGroupField, BooleanToggle, PasswordInput, EditableText, ColorPicker). Docs come from `docs-data.mjs` (build fails if an entry is missing). Demos in `demos/<Name>.jsx` double as the shipped `.jsx` usage examples, compiled inline into each card.
- **Excluded on purpose**: toolbar/* (trivial slot wrappers — chrome classes cover it), EntityCombobox/VariableCombobox/CommandPalette (live entity search), ExpressionEditor (CodeMirror), dashboard/* (tanstack table; future candidate), LanguageFlag/LanguagePicker (flag-icons css dep), versioning/onboarding/collab surfaces (product flows, not design parts). Screenplay layout classes still excluded (legacy DaisyUI tokens); only Courier Prime `@font-face` ships.
- **Gotchas found**: `BooleanToggle.mode` is `"two_state" | "tri_state"` (not "tri"); reka single ToggleGroup emits `undefined` on deselect (documented in its prompt.md); `app.css` defines `.toolbar-input` twice — the synced chrome copy is the effective cascade; dark class belongs on `<html>`/`<body>` so teleported overlays inherit (adapters also propagate via a theme provide).
- **No `_ds_sync.json`** — custom shape, no converter recipe; un-anchored stays the honest state. A re-sync: rebuild, re-run verify.mjs, re-upload everything.
- **App-generated remote files** — `_ds_manifest.json`, `_adherence.oxlintrc.json`: never upload or delete them.
